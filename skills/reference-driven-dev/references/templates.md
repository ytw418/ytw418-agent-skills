# 단계별 문서 틀

## 1-reference.md
```markdown
# <참고 서비스> — <기능/화면> 분석 (<YYYY-MM-DD>)
- 본 경로: 웹 URL / 앱 버전·기기 / 도움말 링크
- 캡처 폴더: ~/bredy-media/<프로젝트>/<날짜-작업>/ref/

## 진입
어디서 어떻게 들어가는지.

## 흐름
| # | 화면 | 보이는 요소 | 사용자 동작 | 결과 | 캡처 |
|---|---|---|---|---|---|

## 상태
빈 상태 / 로딩 / 오류 / 권한 없음 — 본 것만, 못 본 것은 "못 봄".

## 눈에 보이는 값
개수·간격·높이·시간·애니메이션 길이 등(측정했으면 방법도).

## 왜 이렇게 했을까 (추정)
- 추정: …
```

## 2-ours.md
```markdown
# 우리 서비스 — <기능/화면> 현황 (<YYYY-MM-DD>, 커밋 <sha>)
## 앱
- 파일: src/…:줄 / 컴포넌트 / 쓰는 API
- 지금 화면 캡처: …
## 웹
- 파일: app/…, components/… / API: pages/api/… / DB: prisma 모델·열
## 우리만의 제약
용어 규칙, 캐시·폴링 기준, 광고 자리, 정책 등.
```

## 3-diff.md
```markdown
| 항목 | 다른 서비스 | 우리 | 차이 | 옮길까 | 이유 |
|---|---|---|---|---|---|
| 시트 끌기 | 손가락을 그대로 따라감 | 손을 떼야 움직임 | 다름 | 예 | 요청 목적 |
| 목록 정렬 | 거리순만 | 거리·최신 | 우리가 더 나음 | 지킴 | |
```

## 4-apply-plan.md
```markdown
# 적용 설계
## 항목 A: <이름>
- 바꿀 곳: 앱 src/… / 웹 components/… / API … / 마이그레이션(추가형만) …
- 우리 식으로: 문구 "…"(용어표), 색 토큰 …, 일부러 다르게 하는 것 …(이유)
- 수용 기준
  - [ ] A1. <예/아니오 문장> — 확인: <화면·동작·뷰포트> 또는 <테스트 이름>
  - [ ] A2. …
## 지킬 것 (회귀 금지)
- 3-diff 의 "지킴" 항목
## 하지 않을 것
- …
```

## 5-prompt.md
```markdown
# 구현 프롬프트 — <주제>

목표: <한 문단. 사용자가 원한 것과 왜>

먼저 읽을 것: 1-reference.md(참고 동작), 2-ours.md(지금 코드), 4-apply-plan.md(무엇을 어떻게). 3-diff.md 는 범위 확인용.

바꿀 파일:
- …

수용 기준(그대로 지킨다):
- A1. …

지킬 규칙:
- 저장소 AGENTS.md 핵심: <DB 안전 / Parity / 용어 / 색 토큰 / 캐시 등 해당 줄>
- 다른 서비스 이름·문구·이미지·아이콘을 코드나 화면에 넣지 않는다.
- 4-apply-plan 의 "하지 않을 것"·범위 밖 리팩터링 금지.

끝나면 남길 것: 변경 파일 목록, 돌린 검사와 결과, 수용 기준별로 직접 확인한 캡처 경로.
```

## 7. 검증자 프롬프트 (Agent, model: "sonnet")
```text
너는 이 변경을 만들지 않은 검증자다. 코드만 읽고 통과시키지 말고, 기준마다 실제로 화면을 띄우거나 테스트를 돌려 판정한다.

읽을 것: <폴더>/4-apply-plan.md(판정 기준), <폴더>/1-reference.md(참고 동작 비교용)
변경 범위: <브랜치/커밋 범위>
띄우는 법: <로컬 서버 명령·포트 / 에뮬레이터·앱 실행 방법 / 테스트 계정 위치>

할 일:
1. 수용 기준마다 통과 / 실패 / 확인 못 함 + 근거(캡처 경로, 테스트 출력).
2. 실패면 기대 vs 실제를 구체적으로.
3. "지킬 것" 항목이 그대로인지.
4. 다른 서비스 문구·이미지가 그대로 들어왔는지, 저장소 규칙(용어·앱·웹 짝·캐시) 위반이 있는지.

결과를 <폴더>/7-verify-<n>.md 에 표로 쓰고, 마지막 줄에 "판정: 통과" 또는 "판정: 재작업 필요(A2, B1)" 를 적어라.
```
