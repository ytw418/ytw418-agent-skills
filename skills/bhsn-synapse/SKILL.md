# bhsn-synapse

BHSN 기획·CS 자료를 `~/Desktop/bhsn/bhsn-synapse/` 에 모은다. 출처 주소·ID·받은 날·갱신 조건은 그 폴더의 `README.md` 가 기준이니 먼저 읽는다. 이 스킬 저장소는 공개라서 회사 주소·ID·고객 정보는 여기에 쓰지 않고 README 에만 쓴다.

## 찾기

1. 여러 자료에 걸친 질문(이 기능을 원한 고객, 관련 정책·지표·미결 질문 등)이면 `온톨로지/README.md` 를 읽고 `onto.py <id>` 로 그 객체와 이어진 것만 본다. 큐 질문이면 `컨플루언스/큐/README.md`(현황 한 장)부터 읽고, 필요한 주제 파일로 내려간다. 다른 질문은 폴더 README 의 자료 목록으로 볼 곳을 고른다.
2. `rg -i "<키워드>" ~/Desktop/bhsn/bhsn-synapse` (없으면 `grep -rni`)로 찾고, 맞는 파일만 읽는다. CSV 는 필요한 열만 골라 본다.
3. 없거나 오래됐으면 원본에서 찾는다. 노션은 다시 받고, 컨플루언스는 `목록.md` 의 원문 링크나 Atlassian MCP `confluence_search`·`confluence_get_page`, 수치는 `posthog-bhsn` 으로 본다.
4. 답에는 근거 파일·원본 링크·수정일을 붙인다. 요약의 `[상충]`·`차이:` 항목은 확정된 값처럼 말하지 않는다. 고객 이름·연락처는 꼭 필요할 때만 쓴다.

## 모으기

넣을 때마다 README 표(위치·내용·원본·받은 날)를 고친다. 주제 폴더(`cs/`, `기획/`, `지표/`, `컨플루언스/`)는 필요할 때 만든다.

### 노션

회사 자동화 크롬(CDP 9224)에 노션이 로그인돼 있어야 한다. 풀려 있으면 `curl -X PUT "http://127.0.0.1:9224/json/new?<노션 URL>"` 로 로그인 탭을 열어 두고 사용자에게 로그인을 부탁한다(직접 로그인하지 않는다).

```sh
node ~/.claude/skills/bhsn-synapse/scripts/notion-export.mjs <노션 페이지 URL> ~/Desktop/bhsn/bhsn-synapse/<주제 폴더>
```

- 노션 자체 내보내기(Markdown & CSV, 하위 페이지 포함)를 받아 푼다. 40쪽 남짓이면 수십 초 걸린다.
- 같은 폴더에 다시 받으면 덮어쓴다. 노션에서 지우거나 이름을 바꾼 페이지까지 맞추려면 그 하위 폴더를 지우고 받는다.
- 노션 내부 API 를 쓰므로 노션이 바꾸면 깨질 수 있다. 작업이 `not_started` 에 머물면 공간·사용자 헤더 문제다(스크립트 주석 참고).

### 컨플루언스

원문은 용량 때문에 저장하지 않고, 주제별 요약과 원문 링크만 둔다. 받을 범위(CQL·경로 정규식)는 폴더 README 에 있다.

1. 읽을 원문을 임시 폴더로 받는다. 인증은 `~/.claude.json` 의 atlassian MCP 설정을 쓴다.
   ```sh
   uv run -q --no-project --with markdownify python -I ~/.claude/skills/bhsn-synapse/scripts/confluence-fetch.py '<CQL>' /tmp/<새 폴더> '<경로 정규식>'
   ```
   쪽수·글자 수를 출력하고, 제목·링크·수정일을 담은 `목록.md` 를 만든다. 본문 링크·이미지는 뺀다.
2. 주제 묶음(30쪽·10만 자 안팎)마다 하위 에이전트에게 요약을 맡긴다. 지킬 규칙:
   - 항목마다 원문 링크(머리말 url)와 수정일을 붙인다.
   - 문서끼리 다르면 최신 값을 따르고 `[상충]` 으로 표시한다.
   - 고객·개인 정보, 계정, 토큰은 뺀다.
   - 파일 하나에 8천 자 안팎으로 쓴다.
3. 주제 파일과 현황 한 장(`README.md`)을 고치고 `목록.md` 를 바꾼 뒤 임시 폴더를 지운다. 갱신할 때는 지난 요약 날짜 뒤에 수정된 문서만 받아 바뀐 부분만 반영한다.

### 온톨로지

`온톨로지/` 는 모은 자료를 객체(제품·기능·니즈·용어·요금제·규칙·고객 구간·고객·고객 발언·유입 경로·경쟁사·지표·과제·미결 질문)와 링크로 엮은 YAML 이다. 타입·속성·링크 정의는 `schema.yaml`, 쓰는 법은 그 폴더 `README.md`. 자료를 새로 넣거나 요약을 고쳤으면 같은 작업 안에서 온톨로지도 고친다.

1. 바뀐 내용을 타입에 맞는 파일(`제품`·`고객`·`시장`·`진행`.yaml)에 객체로 더하거나 고친다. 원문을 옮겨 적지 말고 한두 문장과 `src`(원문 링크)·`date` 만 둔다.
   - 새 통화 메모 → Customer·Insight(`ins.<이름>.<번호>`). 연락처는 옮기지 않는다.
   - 새 정책·결정·일정 → Policy·Initiative. 문서끼리 다르면 Question(kind 상충)에 안과 날짜를 적고 `lean` 에 지금 따르는 쪽을 쓴다.
   - 새 수치(PostHog 등) → Metric 에 정의(`def`)·값·기간.
2. 맞는 타입·링크가 없으면 `schema.yaml` 부터 고친다. 기존 id 는 바꾸지 않는다(다른 객체가 링크로 가리킨다).
3. 검사한다. 오류가 없어야 끝난다.
   ```sh
   cd ~/Desktop/bhsn/bhsn-synapse/온톨로지
   uv run -q --no-project --with pyyaml python -I onto.py        # 링크·속성 검사
   uv run -q --no-project --with pyyaml python -I onto.py <id>   # 고친 객체와 이어진 것 확인
   ```
4. 객체 수가 바뀌면 `온톨로지/README.md` 의 파일 표 개수와 '지금 그래프가 보여 주는 것'을 고친다.

통화 메모처럼 양이 많은 원문은 하위 에이전트에게 형식(타입별 속성·쓸 수 있는 id 목록·연락처 금지)을 주고 YAML 을 쓰게 한 뒤, 연락처가 없는지 grep 하고 `onto.py` 로 검사한다.

### PostHog (`posthog-bhsn`)

- 회사 PostHog 는 Claude Code MCP `posthog-bhsn`(개인 키, 읽기·쓰기)이다. 브리디 PostHog(claude.ai 커넥터)와 섞이지 않게 시작할 때 `project-get` 으로 프로젝트를 확인한다.
- 지표를 남길 때는 `지표/<YYYY-MM-DD>-<주제>.md` 에 질문, 결과 표, 다시 돌릴 HogQL 이나 인사이트 링크를 함께 쓴다.
- 쓰기(인사이트·대시보드·주석)는 사용자가 시킬 때만 한다. 기능 플래그·실험은 운영 동작이 바로 바뀌니 바꾸기 전에 확인받는다.

## 지킬 것

- 고객 개인정보가 들어 있으니 폴더 내용을 외부(슬랙·깃허브·웹)에 올리지 않는다. `~/Desktop/bhsn` 은 원격이 없는 로컬 git 이므로 원격을 붙이지 않는다.
- 회사 브라우저 작업은 회사 자동화 크롬(9224)에서만 하고, 자기 탭을 열었으면 닫는다.
