# 지라 QA 리뷰용 정리 (jira-qa-review)

QA·CS가 "무엇이 만들어졌고 어떻게 쓰는지"를 한 번에 읽게 한다. 2026-11-04 ALLIBEE-1612(체결본 엑셀 다운로드)에서 처음 했다. 회사(BHSN) 저장소 기능 티켓 대상.

## 원칙

- 지금 상태 그대로만 쓴다. 어려운 내용(파일 경로·API 이름·구현 방식), 결정 안 된 것, 남은 할 일, SP, BE 요청, i18n 행, 옛 목업은 모두 뺀다. 만들지 않은 기능(기획에만 있던 것)도 뺀다
- 문장은 짧은 평서문("~한다", "~뜬다"). 사람 이름은 쓰지 않는다
- 티켓 상태 전이는 하지 않는다. 옛 첨부는 지우지 않는다(본문에서만 뺀다)

## 1. 사실 모으기

- PR 본문·최종 diff에서 실제로 만든 것만 뽑는다(버튼 위치, 상태별 동작, 권한·잠금, 문구, 파일 이름 등). 기존 티켓 본문은 링크 줄(원페이저·스토리)만 가져온다

## 2. 스크린샷 (dev 실제 API)

- 로컬 개발 서버(워크트리) + 회사 자동화 크롬 9224 격리 컨텍스트로 찍는다. 로그인·녹화 방법은 `api-temp-patch` 스킬 7절(dev-login 은 그 스킬 `scripts/dev-login.mjs`). 사용자에게 로그인을 부탁하지 않는다
- 플로우 순서대로: 빈 상태 → 기본 화면 → 마우스 올림(툴팁) → 클릭 결과(토스트·모달) → 조건을 바꾼 경우 → 같은 기능이 있는 다른 화면
- 데이터가 비면 dev 샘플을 직접 만든다(예: 빈 목록에 파일 업로드). 만든 데이터는 보고에 적는다
- 다운로드 기능이면 `page.waitForEvent('download')` 로 받아 파일이 생기는지 확인하고, 내용도 이미지로 만든다
  - xlsx: `python3 -I scripts/xlsx2html.py "<제목>" <파일.xlsx> > out.html` (표준 라이브러리만, 날짜·금액 서식 반영) → `node scripts/html-shot.mjs out.html out.png`
- 찍은 이미지는 전부 열어 보고, 이름을 `done-NN-<장면>.png` 로 붙인다(옛 첨부와 겹치지 않게)

## 3. 본문 쓰기 (구조 고정)

```markdown
원페이저 [제목](URL) · 스토리 [KEY](URL) · PR [#번호](URL)

## 한 줄 요약
<어디서 무엇을 누르면 무엇이 되는지 한 문장>

## 주요 변경사항
- <사용자가 보는 변화 한 줄씩: 새 버튼·화면, 범위, 비활성·로딩·토스트, 권한, 파일 이름·내용>

## 작업 내용 플로우
화면은 dev 실제 API로 찍었다(YYYY-MM-DD, 워크스페이스 ...).

### 1. <장면 제목: 어디서 무엇을 하면 어떻게 된다>
<한두 문장>

![](done-01-....png)

## QA 체크리스트
- <데이터가 생기는지 / 조회되는지 / 다운로드·저장되는지 / 결과물(파일)이 맞는지 / 조건 반영 / 다른 화면에서도 / 권한> 수준으로 5~8개
```

Jira MCP 서식 함정: `{id}`·한글 굵게·`[버튼]`·코드 옆 `+` 는 깨진다(`:id`·〔〕로 대체). 체크박스 `- [ ]` 는 일반 목록으로 바뀐다.

## 4. 올리기 — 첨부 → 본문 → 이미지 박기 (순서 지킴)

1. 첨부: Jira MCP 는 세션 작업 폴더 밖 파일을 못 올린다 → 작업 폴더 안 임시 폴더(`.tmp-<번호>`)로 복사 → `jira_update_issue` 의 `attachments` 로 올림 → 임시 폴더 삭제
2. 본문: `jira_update_issue` 의 `fields.description` 에 3절 마크다운을 넣는다(첨부와 같은 호출이어도 된다)
3. 이미지 박기: `node scripts/jira-embed.mjs <티켓>`
   - 왜: Jira MCP 는 `![](파일)`·`!파일!` 을 본문 이미지로 연결하지 못해 글자로 남는다. 이 스크립트는 회사 크롬(9224) 기본 컨텍스트의 Jira 로그인 쿠키로 REST 를 부른다(토큰 안 씀, 자기 탭만 닫음)
     - v2 PUT: `![](파일)` 을 wiki `!파일!` 로 바꿔 저장 → Jira 가 같은 이름 첨부와 연결한다. MCP 로 저장하면 옛 본문 이미지가 끝에 다시 붙으므로(2026-11-04 ALLIBEE-1680), 본문 마지막 글 뒤에 이미지만 남은 줄은 지운다 — 본문을 이미지로 끝내지 않는다
     - v3 PUT: 각 첨부의 원본 크기를 재서 ADF media 노드에 넣는다. 크기가 없으면 작은 카드(226x141)로만 보인다
   - 출력 `names=N media=N missing=- v3 PUT 204` 이면 성공. `missing` 에 이름이 있으면 그 첨부가 없다
   - 이미 박힌 티켓에 다시 돌려도 안전하다(크기만 다시 넣는다). 본문을 MCP로 다시 저장했으면 반드시 다시 돌린다
4. 확인: `node scripts/jira-shot.mjs <티켓> /tmp/<번호>/jira.png '<본문 글귀>'` 로 실제 화면을 찍어 보고, 출력된 본문 이미지 크기가 740x… 처럼 본문 폭이면 통과(156x125 는 첨부 패널 썸네일이라 무시)

Playwright 는 `~/Desktop/bhsn/allibee-frontend/node_modules/playwright` 를 쓴다. 다른 곳이면 `PW_MJS=<경로>/playwright/index.mjs` 로 넘긴다. Jira 로그인이 풀려 있으면 사용자에게 알리고 로그인 탭을 열어 둔다.
