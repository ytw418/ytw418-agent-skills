# Allibee generated workflows

## Workflow matrix

| 대상 | Workflow file | 생성 branch | PR title | 허용 generated 경로 |
| --- | --- | --- | --- | --- |
| Cue i18n | `generate-cue-i18n.yml` | `generate-cue-i18n` | `CUE I18N GENERATE` | `apps/cue/src/lib/i18n/generated/` |
| Cue type | `generate-cue-type.yml` | `generate-cue-type` | `CUE TYPE GENERATE` | `apps/cue/src/lib/api/generated/` |
| Contract i18n | `generate-allibee-i18n.yml` | `generate-i18n` | `ALLIBEE I18N GENERATE` | `lib/locales/` |
| Contract type | `generate-allibee-type.yml` | `generate-type` | `ALLIBEE TYPE GENERATE` | `lib/api/generated/` |

모든 workflow는 `workflow_dispatch`이며 `develop`을 base로 생성 PR을 연다.

## 실행과 run 고정

```bash
workflow=generate-cue-i18n.yml
started_at=$(date -u +%Y-%m-%dT%H:%M:%SZ)
gh workflow run "$workflow" --ref develop
gh run list --workflow "$workflow" --event workflow_dispatch --limit 10 \
  --json databaseId,createdAt,status,conclusion,url,headSha
```

`createdAt >= started_at`인 run을 선택해 ID를 기록한다. 다른 사용자의 실행을 단순히 최신 run이라고 가정하지 않는다.

```bash
gh run watch <run-id> --exit-status
gh run view <run-id> --json status,conclusion,url,headSha
```

장시간 실행은 한 번에 오래 block하지 말고 짧게 poll한다.

## 생성 PR 확인

```bash
gh pr list --state open --base develop --head <생성-branch> \
  --json number,url,headRefOid,mergeable,statusCheckRollup
```

생성 PR이 없으면 workflow의 `Check for changes`와 `Make changes & Open PR` 로그를 확인해 `no changes`와 실패를 구분한다.

## 충돌 방지

- workflow 실행 전 같은 생성 branch의 open PR을 먼저 처리한다.
- remote branch만 남아 있으면 소유권과 연결된 PR을 확인한다.
- 고정 branch를 자동 삭제하거나 force push하지 않는다.
- 생성 PR diff에 허용 경로 밖의 파일이 있으면 자동 merge하지 않는다.
- base, head, title, `Auto-generated by an action` body, workflow 실행 시점과 PR 생성 시점이 모두 일치할 때만 자동 merge한다.
- 사람이 만든 feature PR에는 이 allowlist를 적용하지 않으며 어떤 경우에도 자동 merge하지 않는다.
