# 브리디 바이럴

작업 폴더 `~/Desktop/pro/bredy-marketing`. 브라우저는 브리디 자동화 크롬(9222) 자기 탭만(`scripts/bpw.sh`). 사이트가 다르면 병렬, 같은 크롬에서 파일 선택 창을 쓰는 게시는 하나씩(11-12 인스타·스레드·블로그를 동시에 돌렸다가 셋 다 멈춤).

## 원칙 (어기면 하지 않는다)

- **운영자·만든 사람임을 밝힌다.** 일반 회원·집사인 척 쓰는 글, "우연히 발견했어요" 류는 쓰지 않는다(표시광고법 뒷광고). 사용자가 허락해도 속는 쪽은 그 커뮤니티 회원이라 바뀌지 않는다.
- **없는 반려동물 이야기를 지어내지 않는다.** 빈칸(`[이름]`)은 브리디 말투로 바꿔 없앤다. 회원 사진은 실제 이름·순위 그대로만(11-12 타로 대신 데뷔전으로 바꾼 이유).
- **홍보 금지 규칙이 있는 곳은 관리자 허락 뒤에만.** 다계정·초대 안 받은 방 입장·카톡 자동 발송·컴퓨터 사용으로 메신저 조작은 하지 않는다(10-15 카톡 자동 발송 금지 결정, 카카오 약관).
- 밤 9시~아침 8시엔 광고성 메시지(DM·채팅) 금지(정보통신망법 50조). 내 계정 게시물은 괜찮다.
- 영업 글엔 이모지 금지, SNS 글은 사람 말투(줄바꿈 많이, ! !! ..., 마침표 생략).

## 지난 기록에서 배운 것 (11-13 정리, 출처는 각 문서)

- **스레드**: 상위 100개 글 87% 가 사진, 본문 해시태그·링크는 1%(하위 16%). 4줄·90자 안팎, 글마다 노리는 반응 하나. 반려동물은 "우리 애 이상한 행동 + 왜 그럴까". 마지막 줄은 링크 대신 "프로필 링크"·"앱스토어 '브리디' 검색". 게시 30분 전후에 남의 글 댓글·내 글 대댓글. 홍보는 20% 이하(`docs/threads-playbook.md` §1~4).
- **인스타 DM**: 1346명 보내 답장 48(3.6%)·가입 5(0.4%), 답은 파충류·크레 쪽에서만. 하루 220명 → 제한(10-15), 새 기기 직후 6분 28명 → 로그아웃(10-19). 하루 30명·45초 간격·제한 문구 보이면 그날 중단.
- **카페**: 정보 댓글(3~4문장 해요체, 링크는 내 블로그 정보글만 맨 끝)은 이틀 30건 삭제 0 — 단 유입 효과는 측정 안 됨. 1:1 채팅·일부 댓글칸은 등급 제한으로 막힘. 카페당 하루 1~2개, 댓글 간격 40초 이상, 경고·삭제 보이면 그 카페 멈춤.
- **공유 카드**: 내 애가 주인공인 결과물 + 마지막 질문, 브리디 표시는 맨 아래 한 줄(`docs/viral-sitter-card.md`). 반응 수치는 아직 없다.
- **로봇천국 카페는 자동 글만으론 7일째 멤버 81명 그대로** — 글 수보다 반응 장치(질문·투표)가 먼저.
- 큰 반응은 소수 글에 몰린다(스레드 stats.tsv) → 같은 콘텐츠를 형식만 바꿔 여러 번 시험하고 잘 된 형식을 반복.

2. 채널별 글: 스레드 500자·해시태그 0·링크 금지 / 인스타 캡션+해시태그 / 블로그 소제목+사진 / 긱뉴스는 개발기. 글엔 항상 사진을 1장 이상 넣는다(11-15 사용자 "글 올릴 때 사진도 같이 넣어야지" — 링크한 화면을 Playwright 모바일 390 폭으로 캡처, 다른 회원 개인정보는 가림). 밴드 사진은 편집기 `label._btnAttachPhoto` 를 눌러 filechooser 로 넣고 '첨부하기' → '게시'(숨은 `input._mediaUploadInput` 에 직접 넣으면 안 붙음). 이미 올린 글은 ⋯ → '글 수정'으로 넣는다 — 편집기 img 에는 링크 미리보기(`_thumb`)도 있어 사진 유무 판정에 쓰지 않는다. 브리디 링크엔 항상 `?utm_source=<사이트>&utm_medium=community&utm_campaign=viral` 을 붙인다(11-14 사용자 지시, PostHog 유입 구분 — 예: `utm_source=fmkorea`). 11-14 이전 글(디시·보배·밴드·OKKY·Sidedock)은 UTM 없음.
3. 바로 올림 채널 게시 → 실제 올라갔는지 주소로 확인.
4. 허락 먼저 채널: 제휴 문의 글을 만들어 사용자에게 보여 준다. 보내는 건 사용자가 확인한 뒤(쪽지·방장 1:1).
5. 보고: 올린 주소, 못 올린 곳과 이유, 다음 날 콘텐츠. 사용자가 직접 할 일(문의 발송 등)은 `~/Desktop/pro/personal-todo/todo.md`.
