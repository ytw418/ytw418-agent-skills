# 브리디 CS·운영 문서

문의 답변, FAQ, 릴리스 노트, 약관 개정을 같은 기준으로 쓴다. 사실은 늘 원본에서 읽고, 기억으로 쓰지 않는다.

## 공통 기준

- **용어:** `bredy_app/docs/terminology.md` 를 먼저 읽는다. '상품·판매·구매'는 쓰지 않는다(분양글·분양·입양, 분양자·입양자, 분양중·분양완료, 유료 분양·무료 분양).
- **말투:** 해요체, 쉬운 말, 짧게. 사과를 늘어놓거나 안심 문구를 깔지 않는다. 무엇이 됐고, 상대가 무엇을 하면 되는지만 쓴다.
- **사실 확인:** 기능·정책은 코드와 약관 원고에서 확인한다. 모르면 "확인해서 다시 알려 드릴게요"로 쓰고 지어내지 않는다.
- **개인정보:** 문의자 이름·연락처·주소·채팅 내용은 초안 밖(공개 저장소·SNS·스크린샷)으로 내보내지 않는다.

## 1. 고객 문의 답변 초안

1. 문의를 한 줄로 요약하고 유형을 고른다: 계정·로그인 / 분양·입양 거래 / 신고·제재 / 결제·광고 / 버그 / 제안.
2. 근거를 찾는다.
   - 정책·제재·환불·게시물 이용: `breeder_web/libs/legal/{terms,policy,privacy}.md` 해당 조항 번호를 찾는다.
   - 기능 동작: 웹 `app/(web)/<경로>`·앱 `src/app/<경로>` 코드를 읽는다.
   - 버그: 재현 단계를 적고 버그 스레드로 넘길 내용을 따로 정리한다.
3. 답변 구조(5줄 안팎): 받은 내용 한 줄 → 결론 → 근거(조항·화면 이름) → 상대가 할 일 → 필요하면 다음 연락 시점.
4. 거래 분쟁은 브리디가 통신판매중개자라 당사자 간 해결이 원칙임을 약관 조항으로 알리고, 신고 경로를 안내한다. 법률 판단처럼 들리는 말은 쓰지 않는다.
5. 보내지 않는다. 초안만 사용자에게 보여 준다(메일이면 작성 카드로).

## 2. FAQ·도움말 글

- 같은 문의가 세 번 넘게 오면 FAQ 후보로 올린다.
- 질문은 사용자 말 그대로, 답은 세 문장 안. 화면 이름과 누를 곳을 정확히 적는다.
- 공개 페이지에 넣으면 웹·앱 동시 개발 규칙과 캐시 규칙(breeder_web `docs/ops/cache-policy.md`)을 같이 지킨다.

## 3. 릴리스 노트

- 원본: 이번 배포에 든 PR 제목·본문(릴리스 PR 의 포함 PR 목록), 앱은 코드푸시·스토어 빌드 기록.
- 사용자에게 보이는 변화만 쓴다. 내부 리팩터·훅·캐시·마이그레이션은 뺀다.
- 형식: "새로 생겼어요 / 바뀌었어요 / 고쳤어요" 세 묶음, 항목마다 한 줄. 스토어 '새로운 기능'은 500자 안(한국어 기준)으로 줄인다.
- 해외 버전(일본어·번체 중국어·영어)은 직역하지 말고 그 나라 사람 말투로 다시 쓴다.

## 4. 약관·운영정책·처리방침 개정

1. 원고는 `breeder_web/libs/legal/{terms,policy,privacy}.md` 다(Notion 아님). 문법은 `scripts/legal-md-to-json.mjs` 머리 주석에 적힌 것만 쓴다.
2. 고치기 전 지금 판을 `libs/legal/history/<문서>-<마지막 적용일>.json` 으로 남긴다(기존 파일 이름 방식을 따른다).
3. 원고 첫 줄 아래 공고일·시행일을 고친다. 회원에게 불리한 변경은 시행 30일 전, 그 밖은 7일 전 공고를 기본으로 잡고 날짜는 사용자에게 확인받는다.
4. `node scripts/legal-md-to-json.mjs libs/legal/<문서>.md > libs/legal/<문서>.json` 으로 다시 만든다.
5. 바뀐 조항을 "지금 → 바뀐 뒤 → 이유" 표로 정리하고, 공지·푸시·메일 문안을 같이 쓴다. 지난 예: `/mnt/project-files/legal/terms-2027-01-01-notice.md`.
6. 이용 규칙(`/content/community-rules`), 금지 개체, 제재 단계처럼 같이 바뀌어야 하는 화면을 찾아 함께 고친다.
7. 법률 판단이 필요한 문장(책임 제한, 개인정보 제3자 제공, 위치정보)은 초안에 "검토 필요"를 달고 사용자에게 넘긴다. 운영 반영은 배포 스레드 절차를 따른다.
