# Token Diet

세션마다 무조건 실리는 고정 비용을 줄인다. 대화 히스토리(매 턴 전체 재전송)와 달리, 고정 오버헤드는 한 번 정리하면 이후 모든 세션에 영구히 적용된다.

## 이 스킬이 다루지 않는 것

- **API 앱의 요청당 비용** → `/claude-api cost-optimize`
- **대화 히스토리 비대화** → `/clear`, 세션 분리, 서브에이전트 위임. 이건 습관의 문제라 설정으로 못 고친다.

## 워크플로우

측정 → 진단 → 적용 → 검증. 측정 없이 제안하지 않는다.

### 1. 측정

사용자에게 `/context` 실행을 요청한다. 에이전트는 이 명령을 직접 호출할 수 없다.

카테고리별 실측치를 받되, 아래 둘을 구분해서 읽는다:

- **`MCP tools`** — 실제로 컨텍스트를 점유 중
- **`MCP tools (deferred)`** — 스키마는 아직 안 실렸고, 이름만 올라가 있다. 표에 큰 숫자로 찍히지만 그만큼을 지금 쓰고 있다는 뜻이 아니다. **지연 로드는 절감이 이미 적용된 상태**이므로, 이 숫자를 절감 목표로 제시하면 과장이 된다. 다만 서버를 아예 제거하면 이름 목록과 `ToolSearch` 탐색 범위가 함께 줄어든다.

### 2. 진단

```bash
python3 scripts/audit.py --days 60
```

세션 로그(`~/.claude/projects/**/*.jsonl`)를 훑어 **실제 호출된** MCP 서버·스킬을 세고, 설치되어 있으나 호출 0회인 항목을 절감 추정치와 함께 출력한다. `--json`으로 기계 판독용 출력.

읽는 법:

- **절대값은 ±30% 근사**다. 한글 비중에 맞춰 보정했지만 여전히 추정이다. 신뢰할 것은 **항목 간 상대 순위**.
- **호출 0회 ≠ 무조건 제거.** 계절성 있는 워크플로우(스프린트 분석, 배포, 온보딩)는 60일간 안 썼어도 다음 달에 쓴다. `--days 120`으로 다시 확인하고, 애매하면 사용자에게 묻는다.
- `audit.py`는 `~/.claude/skills/*`만 센다. 플러그인 스킬(`oh-my-claudecode:*`, `figma:*`)은 빠져 있으니 `/context` 실측과 합계가 다르다. 플러그인은 개별 제거가 아니라 플러그인 단위로 끈다.

### 3. 적용

**전부 되돌릴 수 있는 방법만 쓴다.** 원본 삭제 금지.

#### MCP 서버

```bash
claude mcp list                    # 현재 등록 목록
claude mcp remove <name>           # 로컬 설정 서버 제거
```

claude.ai 커넥터(`claude_ai_*`)는 CLI로 못 지운다 — claude.ai 커넥터 설정에서 끄도록 안내한다.

우선순위:
1. **연결 실패 상태로 방치된 서버** — 죽어 있으면서 이름은 계속 차지한다. 가장 먼저 제거.
2. **같은 백엔드 중복** — 호출 수가 적은 쪽을 제거. `audit.py`의 "중복 백엔드 의심" 섹션이 짝을 찾아준다.
3. **호출 0회 서버**.

#### 스킬 (이 환경의 구조를 반드시 먼저 이해할 것)

`~/.claude/skills`는 심링크 팜이다:

```
~/.claude/skills
  → ~/.local/share/agent-skills-sync/claude/skills/   (런타임 디렉토리)
      <skill-name> → ~/Desktop/bhsn/ytw418-agent-skills/skills/<name>   (개인 레포)
      <skill-name> → ~/Desktop/bhsn/bhsn-claude-code/skills/<name>      (아카이브된 구 레포)
```

런타임 항목은 **전부 심링크**다. 따라서 비활성화는 링크만 끊으면 되고 원본은 남는다:

```bash
RUNTIME=~/.local/share/agent-skills-sync/claude/skills
rm "$RUNTIME/<skill-name>"        # 심링크만 삭제 — 원본 스킬은 레포에 그대로
```

되돌리기는 sync 재실행:

```bash
~/Desktop/bhsn/ytw418-agent-skills/scripts/sync-skills.sh
```

**주의: sync를 다시 돌리면 끊었던 링크가 전부 복구된다.** 영구히 빼려면 레포 `skills/<name>`을 지우고 커밋해야 한다. 사용자에게 "이번 세션만 테스트"인지 "영구 제거"인지 확인하고 진행한다.

#### 서브에이전트

`~/.claude/agents/<name>.md`를 `~/.claude/agents-disabled/`로 옮긴다. 디렉토리가 없으면 만든다.

#### 메모리 파일

`MEMORY.md`는 프로젝트 메모리의 인덱스라 매 세션 통째로 실린다. 항목이 쌓이면 여기가 단일 최대 고정 비용이 된다.

가지치기 기준 — **완료되어 더 참조하지 않을 것**만 지운다:
- 머지·배포까지 끝나고 후속이 없는 티켓 항목
- 폐기된 브랜치·아카이브된 레포를 가리키는 항목
- 같은 주제로 갈라진 중복 항목 → 하나로 합친다

**남길 것**: 재발하는 함정(gotcha), 아직 진행 중인 작업, 반복 적용되는 사용자 피드백. 이건 줄 수가 아니라 재사용 빈도로 판단한다.

지우기 전에 해당 메모리 파일 본문도 함께 지운다 — `MEMORY.md` 줄만 지우면 고아 파일이 남는다.

### 4. 검증

정리 후 **새 세션에서** `/context`를 다시 찍어 전후를 비교한다. 같은 세션에서는 이미 로드된 프롬프트가 안 바뀐다.

사용자에게 보고할 때 추정치가 아니라 실측 차이를 쓴다.

## 보고 형식

절감폭 순으로 정렬하고, 각 항목에 **근거(호출 0회 / 중복 / 실패 상태)**를 붙인다. 근거 없는 제거 제안은 하지 않는다.

계절성이 의심되거나 사용자 워크플로우의 핵심으로 보이는 항목은 **제거 목록이 아니라 확인 목록**에 넣는다.
