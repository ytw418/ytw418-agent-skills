# 원페이저 → 티켓 → 기획·시안 → 가짜 API 개발 (allibee-onepager-flow)

기획자(주로 PO)가 쓴 원페이저 하나를 받아 FE 담당자가 착수부터 개발 화면 영상까지 끝낸다. 단계마다 끝나면 사용자에게 보고하고, 사용자가 "시안만"·"티켓만"처럼 범위를 정하면 그 단계에서 멈춘다.

이 저장소는 공개다. 회사 주소·고객 이름·내부 ID 는 이 파일에 쓰지 않는다.

## 0. 입력 확인

- 원페이저 Jira 키(여러 개 가능). `jira_get_issue` 로 제목·작성자·본문·링크·에픽(parent)을 읽는다.
- 같은 원페이저로 만든 내 스토리가 이미 있는지 `issuelinks` 와 `assignee = currentUser()` 로 먼저 찾는다. 있으면 새로 만들지 않는다.
- 일정·우선순위는 스프린트 분배 글(Slack 등)을 사용자가 주면 그대로 쓴다. 없으면 묻지 말고 비워 둔다.

## 1. 내 스토리 티켓 (jira-bhsn)

- 유형은 **스토리**. 하위작업(Subtask)으로 만들지 않는다 — 보드에 안 보인다(2026-11-24).
- 제목: `[FE][<원페이저 제목의 [영역]>] <원페이저 제목>`.
- 담당자 본인, 스프린트는 원페이저와 같은 활성 스프린트, 에픽은 원페이저의 parent 가 있으면 같은 에픽.
- 원페이저와 `Relates` 로 연결한다.
- 본문은 짧게 이 순서로 쓴다:
  ```
  ## 일정·우선순위
  - <이번 스프린트 먼저 / 12월 이후 / 추후> (<근거: 날짜·누가>)
  - 우선순위: High|Medium|Low
  ## 내용
  - 상위 원페이저: <KEY> (작성: <이름>)
  - <원페이저 요지 3~5줄>
  ## 확인 필요
  - <원페이저의 '확인 필요'·미결 정책>
  ```
- 우선순위 필드(priority)도 본문과 맞춘다.

## 2. 기획 (hjjm-prd, 필요할 때)

- 원페이저가 이미 화면·문구까지 정해져 있으면(시안 첨부·prototype 등) 이 단계를 건너뛰고 3·4단계로 간다.
- 정책이 비어 있거나 화면이 여러 개면 `hjjm-prd` 로 화면 상태·수용 기준·필요한 BE API(요청·응답 필드)를 정리한다. 원페이저에 없는 결정은 '목업에서 임의로 정한 것(확인 필요)'으로 따로 적는다. 확정처럼 쓰지 않는다.

## 3. 목업 시안 + 흐름 영상

- 위치: 원본 HTML 은 `~/Desktop/bhsn/mockups/<스토리 KEY>/`, 영상·캡처 결과물은 저장소 밖 `~/bredy-media/bhsn/<YYYYMMDD>-<KEY>/` (사용자 전역 규칙 16절 — 쓰고 나면 지운다).
- 목업 HTML 규칙(예: `mockups/ALLIBEE-2173/template-lock-mockup.html`):
  - 1440×900 고정, Pretendard, 색·간격은 큐 실제 값(네이비 `#001739`, 선 `#E1E3EB`, 보조 `#636570`)을 쓴다. 문구는 `apps/cue/src/lib/i18n/locales/ko.ts` 의 기존 문구를 먼저 찾아 맞춘다.
  - 장면 함수 배열 `SCENES = [[fn, 초], ...]`, `renderAt(t)` 로 그 시각의 화면을 그린다. 하단 캡션 바에 역할(마스터·멤버)과 한 줄 설명, 가짜 커서.
  - `window.TOTAL`, `window.SHOTS = [['<파일이름>', 초], ...]` 를 내보낸다. `?s=N` 은 N번 장면에 멈춤, `?record=1` 은 녹화용.
- 녹화: `node scripts/record-mockup.mjs <mockup.html> <outDir> <영상이름>` — 회사 자동화 크롬(9224)에 자기 탭을 열어 프레임을 캡처하고 ffmpeg 로 mp4, `SHOTS` 시각마다 PNG 를 남긴다. `QUICK=1` 이면 PNG 만.
- 확인: PNG 를 전부 열어 본다. 영상은 `ffmpeg -i x.mp4 -vf "fps=1/2,scale=360:-1,tile=6x4" /tmp/sheet_%02d.png` 로 모아 끝까지 본다. 커서가 누르는 버튼을 가리키는지, 캡션이 화면을 가리지 않는지 본다.
- 티켓에 올리기: Jira MCP 는 세션 작업 폴더 밖 파일을 못 올린다 → 작업 폴더 안 `.tmp-<KEY>/` 로 복사 → `jira_update_issue` `attachments` → 임시 폴더 삭제. 본문에 '## 목업 시안 (1차, 날짜)' 절(장면별 한 줄 + `![](파일)`)과 '목업에서 임의로 정한 것' 절을 넣는다. 본문 이미지 박기는 `jira-qa-review` 의 `scripts/jira-embed.mjs`(실패하면 첨부만 두고 보고).

## 4. 가짜 API 로 개발 (api-temp-patch)

- 시안을 사용자가 괜찮다고 한 뒤에 시작한다. 대상 저장소·경로 규칙은 사용자 전역·회사 규칙(큐 + React MFE)을 따른다.
- `api-temp-patch` 1~5절대로: 생성 API 코드를 BE 가 낼 모양으로 먼저 고치고, 없는 API 는 `fake/<KEY>.ts` 가짜 응답으로 화면을 만든다. 2단계에서 정리한 BE API 를 BE 담당 티켓·댓글로 넘길 문구도 함께 만든다(보내기는 사용자 승인 뒤).
- 브랜치·커밋·PR 은 `jira-bhsn` 규칙.

## 5. 개발 화면 스크린샷·영상

- `api-temp-patch` 7절대로 로컬 개발 서버 화면을 단계 라벨·가짜 커서와 함께 녹화하고, 가짜 응답 전환으로 오류·빈 상태까지 담는다. 결과물 위치는 3단계와 같다.
- PR 본문과 스토리 티켓에 올린다(3단계 '티켓에 올리기'와 같은 방법).

## 끝난 뒤 (이 스킬 범위 밖)

- 작업이 완전히 끝나 demo 에 올리기 전에 QA·CS 공유용 정리는 `jira-qa-review` 로 따로 한다.
- 결과물 폴더(`~/bredy-media/bhsn/...`)는 티켓·PR 에 올려 쓰임이 끝나면 지운다.

## 보고

단계마다 ① 만든 것(티켓 키·파일 경로·첨부 수) ② 임의로 정한 것 ③ 실패·건너뛴 것과 이유 ④ 다음 단계를 짧게 쓴다.
