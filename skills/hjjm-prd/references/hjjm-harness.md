# HJJM 하네스 구조 (10장 설계 자료 기준 재구성)

> 원본: 「HJJM — 개발 실행 오케스트레이션: 기획과 디자인을 검증 가능한 제품으로」 10장.
> 하네스 코드 자체가 아니라 설계 자료에서 구조·규칙을 뽑아 정리한 문서다.

## 목차
1. 목적
2. 입력 계약 (PRD + .pen)
3. 구성요소와 실행 원장
4. 실행 순서 (입력 → Done)
5. 의존성과 병렬 규칙
6. Done 판정 검사
7. 실패 분류와 다음 조치
8. 화면(Overview / Board / Flow / KB)
9. 플랫폼 확장
10. 이 구조로 하네스를 만드는 방법

## 1. 목적
사람의 의도(무엇을 만들지 = PRD, 어떻게 보여야 할지 = 디자인)를 실행과 검증으로 연결하고,
그 과정에서 생긴 **실패 원인 · 수정 가설 · 검증 결과**를 지식으로 남겨 다음 개발에 재사용한다.

## 2. 입력 계약
| 입력 | 정의하는 것 | 필수 내용 |
|---|---|---|
| PRD | 동작 의도 | 사용자와 기능 / 화면 상태와 오류 처리 / 예·아니오로 판정할 수용 기준 |
| .pen 디자인 | 시각 의도 | 편집 가능한 프레임·컴포넌트 / 레이아웃·색·폰트·모션 / 화면 상태별 비교 기준 |

입력에는 세 가지 고정이 붙는다: **입력 식별값 고정**(어떤 PRD·디자인 버전인지), **요구사항과 화면 연결**(추적표), **담당 이슈와 검사**(누가 무엇을 만들고 무엇으로 검사하는지).

## 3. 구성요소
```
PRD + .pen ─▶ Controller ─▶ Scheduler ─▶ 격리된 Builder ─▶ 플랫폼 Verifier
                 │              │               │                 │
                 └──────────────┴───── 실행 원장 (단일 진실) ──────┘
                                        ▲
             Durable Runner (프로세스 실행·종료 관리)
             Overview / Board / Flow / KB (읽기 전용 뷰)
```
| 구성요소 | 역할 |
|---|---|
| Controller | 입력을 이슈로 분해하고 상태 전이를 결정한다 |
| Scheduler | 의존성을 보고 준비된 이슈를 동시 배정한다 |
| Builder | 격리된 작업 공간(worktree)에서 담당 파일만 수정하고 후보 SHA를 보고한다 |
| Verifier | 플랫폼별 검사 명령을 실행하고 결과·증거를 수집한다 |
| 실행 원장 | 입력 / 이슈 / 시도 / 후보 / 검사 기록. 모든 컴포넌트가 여기에 쓰고 여기서 읽는다 |
| Durable Runner | 프로세스 실행과 종료를 관리해 재시작 후에도 원장을 이어 읽게 한다 |
| 화면 | 원장을 읽기만 한다. **화면은 실행 권한과 Done 판정을 만들지 않는다** |

## 4. 실행 순서
1. 사용자가 PRD·디자인 제출
2. Controller가 입력 식별값과 이슈 DAG를 원장에 기록
3. Scheduler가 준비된 이슈를 Builder 풀에 병렬 배정
4. Builder가 변경과 후보 SHA를 보고
5. Controller가 통합 후보 검사를 Verifier에 요청
6. Verifier가 검사 결과와 증거를 반환
7. 실패면 수정 후 4부터 반복
8. 필수 검사 전부 통과 시 Done 기록

모든 보고와 검증은 같은 입력 식별값과 후보 SHA를 추적한다.

## 5. 의존성과 병렬 규칙
- 순서: **공통 계약(모델/API/스키마) → 화면 구현 · 업무 기능 · 데이터 연동(병렬) → 통합 후보 QC/QA**
- 선행 결과가 후행 이슈의 기준 SHA를 결정한다.
- 같은 파일에는 담당자 한 명. 충돌 자원과 통합 순서는 직렬화한다.
- 독립된 작업은 동시에 실행하고, 공유 결과가 필요한 작업은 기다린다.

## 6. Done 판정 검사
| 검사 | 수용 기준 |
|---|---|
| 빌드 | 통과. 막히면 종속 검사는 미실행 |
| 정적 / 단위 / 통합 | 실행한 필수 테스트 전부 통과, 단위 coverage 80% 이상 |
| 실행 / 화면 / E2E | 통과, E2E 자체 재시도 0회 |
| 접근성 / 성능 / 보안 | 접근성 serious·critical 0건, 보안 high·critical·secret 0건 |
| 기획·디자인 대조 | 화면 상태별로 PRD·디자인과 일치 |
| 독립 검토 | 작성자와 다른 검토자 승인 |

Done 기록 = **최종 SHA/tree + 입력 식별값 + 검사 범위 + 증거**. 이 넷이 일치해야 완료다.

## 7. 실패 분류
| 실패 유형 | 다음 조치 | 유지하는 것 |
|---|---|---|
| 제품 결함 | 관련 Builder에 코드와 수정 가설 전달 | 통과한 선행 작업 |
| 검사 환경 오류 | 동일 후보로 검사 환경 복구 후 재검사 | 제품 코드와 후보 |
| 입력 형식 문제 | 해당 변환·파싱 수정 | 검증된 디자인 추출 |
| 권한 / 신원 문제 | 실행 중단, 권한·신원 확인 | 기존 시도와 실패 기록 |

문제 → 가설 → 변경 → 검사 결과가 한 줄로 이어져 KB(지식)로 남는다.

## 8. 화면
같은 원장을 다른 관점으로 보여준다. Overview(프로젝트·차단 상태), Issue Board(담당자·단계·시도 횟수),
Flow(의존성과 병렬 흐름). 후보 SHA와 검사 증거로 원인을 추적하고, 재시작·새로고침 후에도 같은 기록을 읽는다.

## 9. 플랫폼 확장
공통 실행 계약 위에 플랫폼 어댑터를 꽂는다: 웹 SaaS(인증·조직·업무 기능), 모바일 앱(기기 실행과 화면 검증),
API/내부 도구(데이터·서비스 연동). 지식은 Snaffle 등으로 다음 제품에 재사용한다.

## 10. 이 구조로 하네스를 만드는 방법
설계 자료의 원칙을 Claude Code 도구로 옮기면 다음과 같다. `assets/harness-workflow.js`가 이 매핑의 구현이다.

| HJJM 개념 | Claude Code 구현 |
|---|---|
| 입력 계약 | 이 스킬의 PRD 템플릿 + `validate_prd.py` (형식 검증 = "입력 형식 문제" 조기 차단) |
| Controller | Workflow 스크립트 본문. PRD의 7장(이슈 표)을 읽어 DAG를 만들고 상태 전이를 코드로 결정 |
| Scheduler | 위상 정렬로 웨이브를 만들고 `parallel()`로 같은 웨이브를 동시 실행. 담당 파일이 겹치면 같은 웨이브에 넣지 않는다 |
| 격리된 Builder | `agent(..., {isolation: 'worktree'})`. 담당 파일 외 수정 금지를 프롬프트로 고정하고 후보 SHA를 schema로 강제 반환 |
| Verifier | 별도 `agent()`가 PRD 8장의 검사 명령을 실제 실행하고 결과·증거(로그 경로, 스크린샷 경로)를 schema로 반환. 자기 코드를 자기가 검사하지 않는다 |
| 실패 분류 | Verifier 결과의 `failureType`으로 분기: 제품 결함→같은 Builder 재시도(가설 전달), 환경 오류→같은 후보 재검사, 입력 문제→중단하고 PRD 수정 요구, 권한→즉시 중단 |
| 실행 원장 | 스크립트가 return하는 ledger 객체(입력 식별값·이슈·시도·후보·검사·증거). Workflow의 journal.jsonl이 durable 기록이며 `resumeFromRunId`로 재개 |
| Durable Runner | Workflow 런타임 자체(재개 캐시, 에이전트 실패 시 null 반환) |
| 화면 | `/workflows` 진행 트리와 반환된 ledger. 판정은 스크립트가 하고 화면은 읽기만 |

핵심 설계 결정 세 가지:
1. **판정을 모델이 아니라 코드가 한다.** Done 여부는 Verifier가 돌린 명령 결과를 스크립트가 게이트 표와 비교해 결정한다. 모델의 "완료했습니다"는 근거가 아니다.
2. **만드는 에이전트와 검사하는 에이전트를 분리한다.** 같은 컨텍스트가 자기 결과를 검사하면 실패를 놓친다.
3. **모든 기록에 입력 식별값과 후보 SHA를 붙인다.** 어떤 PRD 버전·어떤 커밋에 대한 검사인지 없으면 증거가 아니다.
