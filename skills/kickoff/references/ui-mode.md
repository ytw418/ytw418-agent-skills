# 화면 모드

대화창 대신 로컬 웹 화면에서 현황을 보고 답한다. 문서(`brief.md`)는 대화창 모드와 같다.
화면은 보여주고 입력을 받기만 한다. 문서를 고치는 것은 에이전트다(프로젝트·작업 단계 변경만 예외로 화면이 바로 고친다).

## 목차
1. 서버 열기·닫기
2. 카드 내기 — cards.json
3. 답 받기 — inbox.json
4. 답 반영하기
5. 화면 구성

## 1. 서버 열기·닫기

- 화면은 `ui/`(React + Vite, 토스 화면 원칙을 따른 자체 컴포넌트)를 빌드한 `ui/dist/`다. `ui/dist/`는 저장소에 함께 커밋되어 있어 따로 설치하지 않아도 된다. `ui/src/`를 고쳤다면 `npm --prefix <이 스킬 경로>/ui install`(처음 한 번)과 `npm --prefix <이 스킬 경로>/ui run build`로 다시 빌드하고 `dist/`도 함께 커밋한다.
- 토스 TDS 패키지(`@toss/tds-mobile`)와 토스 아이콘·이미지는 쓰지 않는다. 약관상 앱인토스 서비스 안에서만 쓸 수 있기 때문이다.
- 이미 열려 있는지 먼저 본다: `~/kickoff/.kickoff-server`에 주소와 pid가 있고 `curl -s <주소>api/board`가 응답하면 그 주소를 쓴다.
- 없으면 Bash `run_in_background`로 연다. 첫 줄에 주소가 찍힌다.
  ```bash
  python3 -I <이 스킬 경로>/scripts/serve.py --root ~/kickoff
  ```
- 사용자가 보는 화면이므로 `open <주소>`로 기본 브라우저에 연다. 자동화 크롬(9222·9224)에 붙이지 않는다.
- 프로젝트 하나만 보여줄 때는 `<주소>#/p/<작업 폴더 이름>`을 연다. 문서 탭을 바로 열려면 `?tab=검토 항목`처럼 붙인다.
- 사용자가 "화면 닫아"라고 하면 그 백그라운드 작업을 멈춘다.
- 서버는 127.0.0.1에서만 열린다. Host가 127.0.0.1·localhost가 아니거나, POST가 JSON이 아니거나, 다른 출처(Origin)에서 오면 거부한다(다른 웹페이지가 문서를 읽거나 고치지 못하게). 쓰는 것은 작업 폴더의 `inbox.json`과 `brief.md` 0장 상태·7장 작업 단계 칸·9장 기록뿐이다.

## 2. 카드 내기 — cards.json

SKILL.md 5·6단계와 같은 규칙(단독/묶음, 추천, 조합 선택지 금지)으로 카드를 정한다. 차이는 셋이다.
- `AskUserQuestion` 대신 작업 폴더에 `cards.json`을 쓴다.
- 한도가 20문항이다.
- 라벨에 `(추천)`을 붙이지 않고 `recommended: true`로 표시한다.

```json
{
  "round": 1,
  "cards": [
    {
      "id": "c1",
      "qids": ["Q-4"],
      "header": "zip 생성 방식",
      "question": "일괄 다운로드 zip을 어떻게 만들까요? (D-1, 백엔드에 제안)",
      "options": [
        { "label": "서버 비동기 작업", "recommended": true, "description": "고르면 무엇이 달라지는지 한 줄", "preview": "| 비교표 마크다운 |" },
        { "label": "서버 동기 스트리밍", "description": "핵심 단점 한 줄" }
      ]
    },
    {
      "id": "c2",
      "qids": ["Q-1", "Q-2", "Q-3"],
      "header": "기획에게 물을 것",
      "question": "이 3개는 기획이 정할 일이에요. 어떻게 할까요?",
      "items": [
        { "id": "Q-1", "text": "누가 일괄 다운로드를 할 수 있나요?", "rec": "조회자는 막기" },
        { "id": "Q-2", "text": "헤더 체크박스는 어디까지 고르나요?", "rec": "지금 페이지만" },
        { "id": "Q-3", "text": "50건을 넘기면 어떻게 하나요?", "rec": "막고 안내하기" }
      ],
      "options": [
        { "label": "질문지에 넣어 기획에게 묻기", "recommended": true, "description": "답이 오면 '결정 필요'로 알려 드려요" },
        { "label": "지금 내가 정하기", "description": "하나씩 카드로 다시 물어볼게요" }
      ]
    }
  ]
}
```

- `id`는 이 파일 안에서만 겹치지 않으면 된다(`c1`, `c2` …). `qids`는 이 카드가 정하는 Q·D 목록이다.
- **묶음 카드는 `items`로 무엇을 묶었는지 카드 안에 보여준다.** 항목마다 `{ "id": "Q-1", "text": "누가 일괄 다운로드를 할 수 있나요?", "rec": "조회자는 막기" }`처럼 쓴다. 숨겨진 '자세히'에만 넣으면 사용자가 무엇을 고르는지 모른다.
- **질문과 선택지는 고르면 무슨 일이 일어나는지 보이게 쓴다.** 선택지 라벨은 동사로, description은 결과로 쓴다.
  - 담당자 묶음: question "이 3개는 기획이 정할 일이에요. 어떻게 할까요?" / 선택지 "질문지에 넣어 기획에게 묻기"(추천, "답이 오면 '결정 필요'로 알려 드려요") · "지금 내가 정하기"("하나씩 카드로 다시 물어볼게요")
  - 본인 기본값 묶음: question "이 3개는 기본값으로 가도 돼요. 그대로 쓸까요?" / 선택지 "기본값 그대로 쓰기"(추천) · "하나씩 정하기"
  - 나쁜 예: "기획 항목 3개를 담당자에게 물을까요?" + "3개 모두 담당자에게 묻기 / 하나씩 보기" — 무엇을 묻는지, 고르면 어떻게 되는지 안 보인다.
- `qids`의 결정 주체와 상태는 카드 문구와 맞아야 한다(예: "본인 기본값" 카드에는 결정 주체가 `본인`인 Q만). 대화창에서 같은 Q를 정했거나 brief에서 그 Q가 `정함`·`범위 밖`이 되면 그 카드를 `cards.json`에서 바로 지운다.
- 답 대기 중인 `답 옴` Q는 카드로 만들지 않는다. 화면이 5장에서 직접 읽어 '반영 / 추가로 묻기 / 빼기'로 보여준다.
- 카드를 낸 뒤 사용자에게 주소와 "화면에서 답하고 '제출'을 누르세요"를 알린다.
- 제출을 기다릴 때는 아래 반복문을 Bash `run_in_background`로 돌린다(최대 1시간). 끝나면 알림이 오므로 그때 4절대로 반영한다.
  ```bash
  until python3 -I -c "import json,sys; sys.exit(0 if json.load(open('<작업 폴더>/inbox.json')).get('submitted') else 1)" 2>/dev/null; do sleep 5; done
  ```
- 사용자가 대화창에서 "제출했어", "반영해줘"라고 해도 바로 4절로 간다.

## 3. 답 받기 — inbox.json

화면이 작업 폴더에 쓴다. 에이전트는 읽기만 하고, 반영한 뒤 옮긴다(4절).

```json
{
  "cards": { "c1": { "choice": "서버 비동기 작업", "note": "", "at": "2026-10-20T14:09:19" },
             "c2": { "choice": "직접 답", "note": "Q-11은 '내보내기'로", "at": "…" } },
  "replies": { "Q-6": { "decision": "반영", "note": "", "at": "…" } },
  "submitted": true,
  "submitted_at": "2026-10-20T14:10:02"
}
```

- `cards.<id>.choice`: 고른 선택지 라벨. `직접 답`이면 `note`가 답이다.
- `replies.<Q-n>.decision`: `반영` / `추가 질문` / `빼기`. `추가 질문`이면 `note`가 추가로 물을 내용이다.
- `submitted`가 `false`면 사용자가 아직 고르는 중이다. 반영하지 않는다.
- 제출한 뒤에는 화면에서 답을 바꿀 수 없다(서버가 409로 막는다). 사용자가 '다시 고치기'를 누르면 `submitted`가 `false`로 돌아간다.

## 4. 답 반영하기

1. 먼저 카드마다 `qids`의 지금 상태와 결정 주체를 brief에서 다시 확인한다. 이미 닫혔거나 결정 주체가 카드 문구와 다르면 반영하지 않고 사용자에게 묻는다.
2. `cards`의 답을 SKILL.md 5단계 3번 규칙대로 `brief.md`에 옮긴다.
   - 묶음 카드에서 "모두 추천대로"를 골랐으면 `qids`의 Q를 모두 그 규칙대로 바꾼다. "하나씩 보기"를 골랐으면 그 Q들로 다음 라운드 카드를 만든다.
   - 묶음 카드의 `직접 답`은 note에 이름이 나온 Q만 그 값으로 바꾸고, 나머지 `qids`는 바꾸지 않은 채 다음 라운드 단독 카드로 다시 묻는다.
3. `replies`는 SKILL.md "답 확인과 결정" 3~4번대로 옮긴다.
4. `inbox.json`을 `inbox-applied/<submitted_at을 YYYYMMDD-HHMMSS로>.json`으로 옮긴다(같은 이름이 있으면 `-2`를 붙인다). 답한 카드는 `cards.json`에서 지운다. 카드가 하나도 남지 않으면 `cards.json`도 지운다. 다음 라운드가 있으면 `round`를 올려 새로 쓴다.
5. `check_brief.py`를 돌려 0장 상태를 갱신한다. 화면은 4초마다 다시 읽으므로 저절로 바뀐다.
6. 채팅으로 무엇을 반영했는지 짧게 보고한다.

## 5. 화면 구성

| 화면 | 내용 |
|---|---|
| 프로젝트 목록 `#/` | 위에서부터 '지금 결정할 것'(답할 카드나 결정할 답이 있는 프로젝트), '진행 중인 프로젝트', '끝난 프로젝트'(접힘). 한 줄에 진행률 링, 프로젝트 이름, 다음 할 일, 결정 수·진행 중 작업 수·담당자별 답 대기(며칠째) 배지 |
| 프로젝트 `#/p/<폴더>` 위 | 제목, 다음 할 일, 단계·막힘·답 대기 배지, 진행률 링(완료 작업/전체), 프로젝트 단계 버튼(진행 중·보류·완료·하지 않기로 하기) |
| 단계 흐름 | 검토 중 → 질문 대기 → 결정 필요 → 착수 가능 → 진행 중 → 완료. 단계마다 작업 수. 질문 대기는 점선 테두리가 돌고, 결정 필요는 주황으로 강조되고, 진행 중은 궤도가 돈다. 작업이 넘어가는 구간에는 흐르는 점선이 보인다 |
| 작업 보드 | 단계별 열에 작업 카드. 진행 중 카드는 로딩이 돌고, 질문 대기 카드는 무슨 답을 며칠째 기다리는지, 결정 필요 카드는 '답 옴'을 보여준다. 단계가 바뀌면 카드가 새 열로 미끄러지며 반짝이고, 완료되면 체크가 그려진다. 카드를 누르면 바텀시트(관련 R·Q·D, 단계 바꾸기), 끌어다 놓으면 착수 가능(자동)·진행 중·완료로 옮긴다 |
| 지금 결정할 것 | 넓은 화면에서는 오른쪽에 붙어 있다. 받은 답(반영하기·추가로 묻기·이 항목 빼기 + 메모)과 `cards.json` 카드(추천 배지, 자세히 보기, 직접 답), '모두 추천대로 고르기', 아래 '제출하기' |
| 문서 탭 | 요약(1·3장, 0장은 접힘), 요구사항, 화면 상태, 검토 항목(상태·담당 필터), 설계, 수용 기준, 질문지(담당자별 복사), 기록 |
