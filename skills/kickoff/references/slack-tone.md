# 질문지 말투 — 회사 Slack에서 쓰는 말투

담당자에게 보내는 질문지(`questions.md`)는 사용자 이름으로 Slack에 그대로 나가는 글이다(사용자가 붙여넣거나, SKILL.md '질문 보내기'로 승인받아 보낸다).
사용자와 동료들이 실제로 쓰는 말투(2026-10-20 회사 Slack 메시지 약 260건 분석)를 따른다.
화면(UI) 문구의 토스식 해요체와는 다르다. 질문지는 동료에게 묻는 업무 글이다.

## 핵심

- **통보하지 않고 묻는다.** 기본값은 "답이 없으면 A로 하겠다"가 아니라 "일단 A로 생각하고 있는데 괜찮을까요?"라는 제안이다.
- **왜 묻는지 먼저 말한다.** "~해서 여쭤봐요", "~때문에 확인이 필요해서요"처럼 이유를 한 줄 붙인다.
- **일정은 내 쪽 사정으로 말한다.** "○/○부터 개발 들어가려고 해서, 그 전에 정해지면 좋을 것 같아요."처럼 쓴다. 상대에게 기한을 걸지 않는다.
- **상대가 고르기만 하면 되게 쓴다.** 선택지를 A/B로 적고, 내가 생각한 쪽을 덧붙인다.

## 쓰는 표현

| 자리 | 표현 |
|---|---|
| 여는 말 | "○○님 안녕하세요! ○○ 관련해서 몇 가지 확인 요청드립니다." 이미 대화 중인 스레드면 인사 없이 "○○님,". 이름을 모르면 이름 없이 "안녕하세요! ○○ 관련해서 …"로 쓰고 절 제목에만 (이름 확인 후 보냄)을 단다 |
| 이유 | "~해서 여쭤봐요", "~싶어서요", "현재는 ~로 되어 있어서 확인 부탁드려요" |
| 질문 | "혹시 ~ 가능할까요?", "~해도 괜찮을까요?", "~로 알고 있는데 맞을까요?", "A로 할지 B로 할지 정해 주시면 좋을 것 같아요" |
| 내 생각 | "일단 A로 생각하고 있는데 괜찮을까요?", "저는 A 쪽이 좋을 것 같아요(이유)", "그냥 제 의견입니다" |
| 일정 | "○/○부터 개발 들어가려고 해서, 그 전에 정해지면 좋을 것 같아요.", "일정 어려우시면 편하게 말씀 주세요!" |
| 미리 정해 둔 것 | "참고로 아래는 일단 이렇게 진행해 보려고 해요. 다르게 생각하시면 말씀 주세요." |
| 마무리 | "확인 부탁드립니다🙏 감사합니다!" |
| 다시 물을 때 | "○○ 건 어떻게 되고 있을까요? ○/○ 개발 시작이라 여쭤봐요." |

- 어미는 '~요'와 '~습니다'를 섞는다. 질문·제안은 '~요/~을까요', 요청·공유는 '~드립니다'를 쓴다.
- 이름 뒤에는 '님'을 붙인다.
- 이모지는 '부탁드립니다' 뒤에 🙏 하나 정도만 쓴다. '감사합니다' 뒤에는 '!'나 '~!'를 붙여도 된다.
- 항목이 여러 개면 번호를 붙이고, 한 항목에는 질문을 하나만 넣는다. 한 문항 끝에 두 번째 요청(법무 확인 등)을 붙이지 않는다.
- **같은 문장을 되풀이하지 않는다.** 한 담당자 절 안에서 같은 문장("일단 A로 생각하고 있는데 괜찮을까요?", "~해서 여쭤봐요")은 두 번까지만 쓰고, 나머지는 위 표의 다른 표현으로 바꾼다. 추천이 늘 A가 되지 않게 선택지는 자연스러운 순서로 둔다.
- **같은 어미도 되풀이하지 않는다.** '~것 같아요', '~여쭤봐요'가 한 절에 세 번을 넘지 않게 "~하려고 해요", "~면 좋겠어요", "~어떨까요?", "~가 편할 것 같아서요" 등으로 바꾼다.
- **이유 줄에는 질문에 없던 사정만 쓴다.** 질문을 다시 말하거나 추천 선택지를 미리 내밀지 않는다(나쁜 예: "51번째를 누를 때 어떻게 보일지 정해 두면 좋을 것 같아서요"). 근거는 내 생각 줄에 한 번만 쓰고, 이유 줄·선택지·내 생각 줄이 같은 근거를 되풀이하지 않는다.
- 이유 줄과 내 생각 줄은 각각 한 문장, 연결어미('~해서', '~는데', '~라')는 한 번만 쓴다. 다른 담당자에게도 묻는다는 말은 괄호로 짧게 붙인다.
- **A/B는 정말 갈릴 때만.** 답이 거의 정해진 문항은 "~해도 괜찮을까요?" 한 문장으로 묻는다. 한 절에서 A/B 문항은 4개 안팎으로 두고, 추천이 모두 A가 되지 않게 자연스러운 순서로 둔다. 질문은 선택지를 고르는 형태로 쓴다("있을까요?" 같은 열린 질문에 A/B를 붙이지 않는다).
- 상대 담당 영역(서버 작업량, 디자인 공수)은 단정하지 않는다. "부담되시면 B도 괜찮아요"처럼 고를 여지를 남긴다.
- **이미 받은 답은 다시 묻지 않는다.** 여는 말에서 "말씀 주신 대로 ~로 맞춰 둘게요!"로 받고, 답에 조건이 남아 정말 확인할 게 있을 때만 그 조건 하나를 묻는다.
- 같은 사실(법 기준 등)은 그것이 필요한 문항 한 곳에서만 설명한다. 같은 대상은 한 이름으로 부른다(마케팅 푸시/광고 푸시를 섞지 않는다).
- **말은 업무 말 그대로 쓴다.** 빼는 것은 코드 경로·UI 부품 이름(헤더 체크박스, 행 메뉴, 토스트)·키 이름·언어 코드뿐이다. 선택·실패·지표·다운로드처럼 회사에서 늘 쓰는 말은 그대로 쓰고, "고르기·못 가져오기·숫자"처럼 일부러 풀어 쓰지 않는다. 한자어가 줄줄이 이어지는 말(야간 판정 기준 시각)만 풀어 쓴다. 백엔드 절에서는 폴링·비동기·상태 코드 같은 기술 용어를 그대로 쓴다.
- 버튼은 "[다시 시도]" 대신 "다시 시도 버튼"처럼, 개수는 "n건" 대신 "3건"처럼 예시 값으로 쓴다.
- 질문 문항 안에서 "확인 부탁드려요"를 쓰지 않는다(마무리 인사와 겹치고 지시처럼 들린다). "확인 부탁드립니다🙏"는 맨 끝에 한 번.
- Jira 티켓이 없으면 묻지 말고 "없으면 제가 하나 만들어 둘게요!"처럼 덧붙인다(한 문항에 물음표는 하나).
- 담당자를 모를 때 묻는 부탁은 번호 문항이 아니라 번호 목록 뒤에 "그리고 혹시 ○○는 어느 분이 맡고 계신지 알 수 있을까요?" 한 문장으로 둔다.
- 참고 목록은 "~하려고 해요"로 끝내고 '~할게요'는 한 절에 한 번까지. 한 항목은 한 문장으로 쓴다.
- 번호 문항에 질문과 다른 결정("파일 이름은 ~하려고 해요")을 붙이지 않는다. 그런 줄은 참고 목록으로 옮긴다.
- 다른 담당자를 묻는 내용과 한 문장에 엮지 않는다("~쪽으로 ○○님께 여쭤보고 있어요" ✕). 내가 아는 대로 쓰고 다른 담당자 이야기는 괄호로만 단다. 다른 담당자와 아직 정하는 값은 확정처럼 쓰지 않고 "그 결정과 같게"로 묻는다(지금 생각하는 값은 괄호로).
- 앞 문항(코드 블록 포함)에 이미 나온 내용은 다시 풀어 쓰지 않고 "위 형태의 ○○"처럼 가리킨다.
- 같은 대상을 두 문항에서 다루면 질문에 범위(토글을 켠 사용자 / 전체 사용자)를 적는다.
- 막힘 문항(답에 따라 일정이 갈리는 것)은 그 담당자 절에서 Jira 문항 바로 뒤에 둔다. "먼저", "위"처럼 순서에 기대는 말은 실제 순서와 맞을 때만 쓴다.

## 쓰지 않는 표현

- "~까지 답이 없으면 ~로 진행하겠습니다", "답이 없는 항목은 기본값으로 진행합니다"
- "회신이 없을 경우 동의한 것으로 간주하겠습니다", "미응답 시"
- "~로 진행합니다", "~할 예정입니다"(통보로 들림)
- "~까지 회신 바랍니다", "~해 주시기 바랍니다", "빠른 확인 바랍니다"(지시·공문체)
- "바쁘실 텐데 죄송하지만", "편하실 때"(사용자가 실제로 쓰지 않는 과한 공손 표현)
- "기획 문서에 없어서", "누락되어", "화면이 아직 없어서", "정의가 없어서", "현재 ~만 있어서"처럼 상대나 현재 서비스가 잘못됐다고 들리는 말. 대신 "~할 때 어떻게 보일지 정해 두면 좋을 것 같아서"처럼 쓴다
- 법 조항 번호·조문 인용, 코드 경로, 언어 코드(en·ja)·키 이름·'라벨' 같은 개발 용어(근거는 brief.md에만 둔다)
- "○○는 넣지 않으려고 해요"처럼 이유 자리에 내가 정한 범위를 섞는 말. 필요하면 "요청 주신 대로 ~로 두려고 해서"처럼 쓴다
- 'OO', '○○', '김PM님', '백엔드 담당자님'처럼 이름 대신 쓴 자리 표시·역할 호칭. 이름을 모르면 "백엔드 쪽"처럼 쓴다
- "기획서의 A와 화면의 B"처럼 두 문서를 맞대는 말, "시안을 바꿔야", "수정이 필요"처럼 상대 결과물을 고쳐야 한다는 말. 내가 이해한 대로 적고 맞는지 묻는다
- 현재 동작을 물을 때 법·규정을 이유로 드는 말(위반 여부를 캐묻는 것처럼 들린다). 이유는 "이번 작업에 같이 맞춰 두려고"처럼 댄다. 법·규정을 설명한 문항에 "지금 그렇게 나가고 있는지 ○○님께 여쭤볼게요"도 붙이지 않는다
- 사물 높임("숫자가 있으실까요"), "사용자께"처럼 과한 높임. "사용자에게", "있을까요"로 쓴다
- 상대 요청을 작게 보는 말("토글 하나 추가하는 작업이라")
- 질문지 본문의 `[Q-n]` 같은 내부 번호(Slack 글이 서식처럼 보인다). 번호 대응은 질문지 맨 아래 '내부용' 절에만 둔다
- 같은 문장에 이모지 여러 개, 느낌표 연타

## 보내기 전 점검

- [ ] 통보·기한 거는 문장이 없다("답이 없으면", "~까지 회신", "진행합니다")
- [ ] 본문에 지어낸 날짜가 없다(원문 일정이 없으면 날짜를 쓰지 않았다)
- [ ] 이름 자리 표시(OO·○○)가 없다. 모르면 제목에 '(이름 확인 후 보냄)'
- [ ] 같은 문장이 한 절에 세 번 이상, 같은 어미('~것 같아요')가 네 번 이상 나오지 않는다
- [ ] 이유 줄이 질문을 다시 말하거나 추천을 미리 내밀지 않는다
- [ ] 한 문장에 연결어미가 두 번 이상 이어지지 않는다
- [ ] 추천이 모두 A가 아니다. A/B가 필요 없는 문항은 한 문장 질문이다
- [ ] 이미 받은 답을 다시 묻지 않는다
- [ ] 번호 문항에 질문과 다른 '~하려고 해요' 결정이 없다
- [ ] 같은 대상을 절 안에서 한 이름으로 부른다(마케팅 푸시/광고 푸시를 섞지 않는다)
- [ ] 다른 절에서 "○○님께 여쭤볼게요"라고 한 항목이 그 사람 절에 번호 문항으로 있다
- [ ] 문항마다 질문이 하나이고, A와 B가 같은 한 가지만 다르다
- [ ] 상대가 답해야 할 것이 참고 목록에 숨어 있지 않다
- [ ] 본문에 Q-n·W-n·법 조항 번호·코드 경로·언어 코드가 없다
- [ ] 다른 담당자 절을 보지 않아도 무엇을 묻는지 알 수 있다
- [ ] Claude·AI 흔적(서명, 🤖, "Generated with", Co-Authored-By 등)이 없다

## 답이 없을 때

답이 없다고 바로 기본값으로 진행하지 않는다. 진행할지는 사용자가 정한다.
- 다시 물을 글: "○○님, 지난번에 여쭤본 ○○ 건 혹시 확인 가능하실까요? ○/○ 개발 시작이라 여쭤봐요🙏"
- 사용자가 "일단 진행하자"고 하면 알리는 글: "○○ 건은 일단 A로 진행해 두었어요. 다르게 생각하시면 말씀 주세요, 바로 맞출게요!"

## 기다림 후속 메시지

담당자가 이미 하기로 했거나 다른 사람이 같은 것을 이미 물었으면(`기다림`) 새 질문지를 쓰지 않는다. 확인이 필요할 때나 3영업일 이상 소식이 없을 때만 짧은 후속 메시지를 제안한다. 보낼 곳은 SKILL.md '질문 보내기'에서 매번 묻는다(원래 스레드 답글이 추천).
- 하기로 한 일을 받을 때: "말씀 주신 ○○ 정해지면 공유 부탁드려요! FE는 그 전까지 ○○ 기준으로 작업해 둘게요🙏"
- 오래 기다릴 때: "○○님, 말씀 주신 ○○ 건 혹시 진행 상황 공유 가능하실까요? FE는 일단 ○○ 기준으로 작업하고 있어요🙏"
- 한 메시지에 한 가지만 묻는다. 하기로 한 일을 다시 해 달라고 하지 않고, 내 쪽 준비 상황을 이유로 댄다.
