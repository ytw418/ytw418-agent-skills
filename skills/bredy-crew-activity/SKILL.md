# 브레디 크루 활동

크루는 운영팀이 직접 굴리는 계정이다. 사람처럼 자연스럽게 쓰되 **운영 계정임을 숨기지 않는다.**

## 위치

- 이 스킬 폴더: `SKILL.md`, `personas.json`(크루 50명), `scripts/crew.mjs`(Node 18+, 의존성 없음), `scripts/listings.mjs`(분양글·경매 등록).
- 같은 내용이 breeder_web 저장소 `.claude/skills/crew-activity/` + `scripts/crew/crew.mjs` 에도 있다. 고치면 두 곳을 같이 고친다.
- **명령은 breeder_web 루트에서 실행한다.** 상태·계획·기록이 그 아래 `.crew/`(breeder_web 가 gitignore)에 쌓인다.

```bash
cd ~/Desktop/pro/breeder_web
CREW=~/.claude/skills/bredy-crew-activity/scripts/crew.mjs   # 동기화된 스킬 경로
```

## 지키는 것 (바꾸지 않는다)

- 이름 뒤 `·크루`, 소개 앞 `브레디 크루 🐾` 를 지우거나 바꾸지 않는다. 글·댓글에서 "크루 아니다", "그냥 일반 유저"처럼 정체를 부정하지 않는다.
- 거래 신뢰를 만드는 행동은 하지 않는다: 입찰, 채팅, 거래 후기, "이 판매자한테 샀는데 좋았어요" 같은 거래 경험담, 특정 판매자·상품 추천. **분양글·경매 등록은 2026-10-12 사용자 결정으로 예외** — 아래 '분양글·경매글 올리기' 절차로, 사용자가 "상품·경매 올려줘"라고 할 때만 한다.
- 키우지 않는 개체를 키운다고 사진으로 꾸미지 않는다. 사진이 필요한 글(자랑·사진)과 혈통은 사용자가 준 실제 사진이 있을 때만 쓴다.
- 의료·응급 질문(거식 2주 이상, 탈장, 출혈 등)엔 일반 정보만 주고 "파충류 진료 가능한 병원에 가 보세요"를 꼭 붙인다. 모르는 건 지어내지 않는다.
- 동네 노출(`regionVisible`)은 켠다(2026-10-10 사용자 결정 — "동네 브리더 많아 보이면 좋다"). 크루도 동네 브리더 목록·홈 동네 섹션에 나온다. 채팅은 여전히 하지 않는다.
- 닉네임은 귀엽고 부드러운 느낌으로 짓는다(예: 크레곤듀·핑크레·몽글게코, 2026-10-10). '샵'·'분양'·'판매'처럼 가게·판매자로 보이는 말은 넣지 않는다(스크립트도 막는다).
- 프로필 사진은 그 크루의 종을 그린 귀여운 캐릭터 그림만 쓴다. 실제 사람 사진, AI로 만든 사람 얼굴은 쓰지 않는다(초상권·사칭, 운영 계정을 실제 회원처럼 보이게 하는 것).
- DB 에 직접 붙지 않는다. 모든 동작은 `scripts/crew.mjs` 가 공개 API 로 한다.
- 운영 서버 실행은 매번 계획을 보여 주고 **사용자 확인을 받은 뒤에만** 한다.

## 크루 역할 (2026-10-19 사용자 결정)

생물 큰 분류(곤충·절지류·파충류·어류·포유류·양서류·식물)마다 6명이 역할을 나눠 맡는다. 역할은 `personas.json` 의 `group`·`role` 에 있고 `node $CREW roles` 로 표를 본다.

| 역할 | 분류마다 | 하는 일 |
|---|---|---|
| 정보 | 1명 | 정보·변이 글 |
| 댓글 | 3명 | 그 분류 글(토론 포함)에 댓글 |
| 토론 | 1명 | 찬반 토론 열기 |
| 질문 | 1명 | 질문·자유·동네(사진 있으면 자랑·사진) 글 |
| 예비 | 남는 8명(파충류 6·포유류 2) | 좋아요·팔로우만 |

- `apply`·`lint` 가 역할을 검사한다(막음): 역할 밖 글 카테고리, 자기 분류가 아닌 `species`, 토론 크루가 아닌 토론, 다른 분류 댓글 크루의 댓글, 예비 크루의 글·댓글. 글쓴이 본인이 자기 글 댓글에 답하는 것은 역할과 상관없이 된다. 분류를 알 수 없는 글(종 없음·스냅샷에 없음)엔 어느 분류 댓글 크루든 단다.
- 역할 크루는 자기 분류의 어느 종이든 쓸 수 있다. 다만 키운다고 말하는 건 그 크루의 `species` 만이고, 다른 종은 "찾아보니", "주변에서 들었는데"처럼 쓰거나 질문으로 쓴다.
- 분류에 크루가 모자라 3명을 옮겼다: c07(카멜레온 + 먹이 곤충 번식) → 곤충, c50(비바리움 등각류·톡토기) → 절지류, c44(수초) → 식물.
- 역할을 바꾸면 `personas.json` 만 고친다(서버 계정·프로필은 그대로).

- 결과는 `.crew/roster.json`(gitignore)에 남는다. 이 파일이 없으면 크루를 다시 만들지 말고 사용자에게 먼저 묻는다(중복 생성 방지).
- 토큰은 파일·로그·답변에 적지 않는다.

## 매번 실행 순서

1. **읽기**: `node $CREW snapshot --pages 5` → `.crew/snapshot.json` 을 읽는다.
   - `posts[]`: 최근 글(본문 600자, 댓글 포함, `author.isCrew`).
   - `recentCrewTitles[]`: 지금까지 크루가 쓴 글 제목.
2. **크루 고르기**: `node $CREW roles` 로 역할표를 보고 이번에 움직일 분류를 고른다. 한 번에 전 분류가 다 움직이지 않게 3~5개 분류(10~20명)만 쓰고, 지난번과 다른 분류를 우선한다. 크루 아닌 사람의 답 없는 질문이 있는 분류는 이번에 넣는다.
3. **계획 쓰기**: `.crew/plan-<날짜>.json` 에 아래 형식으로 쓴다. 기본 분량은 글 4~8 · 토론 0~3 · 댓글 15~30 · 좋아요 20~50 · 팔로우 5~15 이다(스크립트 상한: 글 15, 토론 7, 댓글 60, 좋아요 120, 팔로우 60, 혈통 5). 쓰기 전에 `references/natural-voice.md` 를 읽는다.
4. **AI 냄새 빼기 (생략하지 않는다)**:
   - `node $CREW lint .crew/plan-<날짜>.json --strict` → 막음(✖)·경고(△)를 고친다. 막음이 남으면 `apply` 도 실행되지 않는다.
   - 그다음 다듬기 서브에이전트(`model: "sonnet"`)에게 `references/natural-voice.md` §6 부탁문을 그대로 준다. 글쓴이가 아닌 눈으로 한 번 더 보게 하려는 것이다. 받은 결과를 다시 `lint --strict` 로 확인한다.
5. **보여 주기**: 사용자에게 요약을 보여 준다. 새 글은 제목·카테고리·크루·본문 앞부분, 댓글은 대상 글 제목 + 댓글 전문, 좋아요·팔로우는 개수와 대상을 보여 준다. 확인을 받는다.
6. **검사**: `node $CREW apply .crew/plan-<날짜>.json --dry-run` (같은 AI 냄새 검사를 다시 한다)
7. **실행**: `node $CREW apply .crew/plan-<날짜>.json`. 동작 사이에 4~12초 쉰다. 끝나면 성공·건너뜀·실패 수와 기록 파일(`.crew/log/*.jsonl`)을 보고한다.
8. **되돌리기(필요할 때)**: `node $CREW cleanup .crew/log/<파일>.jsonl --dry-run` → 확인 뒤 `--dry-run` 없이. 그 실행에서 만든 글·댓글만 지운다(혈통은 관리자 화면에서 회수).

## 분양글·경매글 올리기 (사용자가 요청할 때만, 2026-10-12 예외)

```bash
node "$(dirname $CREW)/listings.mjs" .crew/listings-<날짜>.json --dry-run   # 크루·사진·길이·출처 줄 검사
node "$(dirname $CREW)/listings.mjs" .crew/listings-<날짜>.json             # 사용자 확인 뒤
```

- 계획 형식은 `.crew/listings-2026-10-12.json` 참고: `products[]`(crew·photo·name·category·productType·dealType·price·description), `auctions[]`(crew·photo·title·category·startPrice·minBidIncrement·hours 1~72·description). 종이 맞는 크루가 올린다.
- **사진은 iNaturalist 사육 개체만**: API `observations?taxon_name=<학명>&captive=true&photo_license=cc0,cc-by,cc-by-sa`. 손 위·사육통 사진이 분양글답다(위키미디어 야생 사진은 "너무 가짜같다"). 가격표·상호가 보이는 사진은 뺀다. CC BY 는 설명 끝에 `사진: 이름 (iNaturalist, CC BY)` 한 줄(CC0 는 계획에 `"cc0": true`). 네이버 카페·인스타 등 남의 사진은 쓰지 않는다.
- 글은 실제 분양글처럼 쓴다(해칭 시기·체중·먹이·직거래 지역·택배). 제목에 '판매'·'상품'은 쓰지 않는다. 경매는 등록 즉시 시작되고 실제 회원이 입찰·채팅할 수 있는데 크루는 답하지 않으니, 실행 전 사용자에게 이를 알린다.
- 기록은 `.crew/log/listings-*.jsonl`(id·사진 id). 되돌리려면 관리자 화면에서 그 id 를 지운다.

{ "edits": [
  { "type": "post", "crew": "c39", "id": 149, "title": "...", "description": "..." },
  { "type": "comment", "crew": "c42", "postId": 137, "id": 39, "comment": "..." }

- 고치기 전 문장은 기록(`.crew/log/edit-*.jsonl` 의 `before`)에 남는다.

## 계획 형식

```json
{
  "actions": [
    { "type": "post", "crew": "c39", "category": "질문", "species": "크레스티드 게코",
      "title": "크레 이유식 하루 걸러 줘도 되나요?",
      "description": "데려온 지 두 달 된 아이인데요...(10~2000자)" },
    { "type": "debate", "crew": "c40", "species": "레오파드 게코",
      "title": "레게 바닥재, 모래 써도 된다 vs 안 된다", "optionA": "써도 된다", "optionB": "안 된다",
      "durationHours": 72, "description": "임팩션 때문에 모래 절대 안 된다는 분도 있고..." },
    { "type": "comment", "crew": "c47", "postId": 1234, "comment": "저희 애들은 이틀에 한 번 줘요. ..." },
    { "type": "comment", "crew": "c47", "postId": 1234, "parentId": 5678, "comment": "맞아요, 온도도 같이 보세요" },
    { "type": "like", "crew": "c02", "postId": 1234 },
    { "type": "follow", "crew": "c03", "userId": 42 },
    { "type": "bloodline", "crew": "c47", "name": "남양주 릴리화이트", "speciesType": "크레스티드 게코",
      "imagePath": "assets/crew/c47-lily.jpg", "description": "...", "originSido": "경기도", "originSigungu": "남양주시" }
  ]
}
```

- `category`: 동네·자유·질문·정보·자랑·사진·변이 (공지·후기 금지). 역할별로 쓸 수 있는 것만(위 '크루 역할'). 동네 글은 그 크루의 동네로 올라간다.
- `species`: 카테고리 이름 그대로(`libs/categoryTaxonomy.ts`, 예: `크레스티드 게코`, `장수풍뎅이`) 또는 큰 분류 이름(`파충류`). 그 크루 분류 안에서만 고른다.
- `debate`: 질문 5~40자, 선택지 1~12자(서로 달라야), `durationHours` 72(기본)·168·24, 설명 1000자까지(없어도 된다). 서버가 크루당 하루 3개, 가입 하루 지난 계정만 받는다.
- 글 본문은 일반 텍스트에 줄바꿈만 쓴다. `## `·`**굵게**`·번호 목록은 블로그 글처럼 보여 쓰지 않는다(`lint` 가 막거나 경고한다). 목록이 꼭 필요하면 `-` 몇 줄까지. 사진 자리 `[[photo:N]]` 는 사진을 붙일 때만 쓴다.
- 사진 글(2026-10-21): 사용자가 준 실제 사진만 `"imagePaths": [".crew/photos/<날짜>/1.jpg", …]`(10장까지, `sips -Z 1600` 으로 줄여 둔다)로 붙이고 본문에 `[[photo:1]]` 줄을 넣는다. 크루가 키우지 않는 동물이면 '언니네·친정' 처럼 남의 아이로 쓴다. 이미 올린 글의 사진은 `edit` 에 `imagePaths` 를 주면 바꾼다. 올린 뒤 `https://imagedelivery.net/OvWZrAz6J6K7n9LKUH5pKw/<id>/public` 이 200 인지 확인한다(10-21 업로드 id 를 잘못 저장해 6장이 404 였다).

## 글 쓰는 법

- **겹치지 않게**: `snapshot.posts[].title` 과 `recentCrewTitles` 에 있는 주제를 다시 쓰지 않는다. 같은 종이라도 다른 각도(계절·먹이·사육장·번식·초보 실수·용품 비교·관찰 일기)를 고른다. 스크립트도 같은 제목을 막는다.
- **분량**: 고른 분류마다 정보 크루 글 0~1, 질문 크루 글 1(질문 위주, 가끔 자유·동네). 질문은 진짜 궁금할 만한 구체적 상황으로 쓴다(나이·기간·온도 같은 숫자 포함). 답이 붙기 쉬운 질문이 좋다. 질문 크루 글엔 같은 실행에서 댓글 크루가 바로 달지 않는다(다음 실행에서 단다 — 답이 너무 빨리 붙으면 짜고 치는 것처럼 보인다).
- **토론**: 그 분류에 진행 중인 토론(`snapshot.posts[].debate.state === "open"`)이 없을 때만 연다. 정답이 갈리는 사육 논쟁(바닥재·합사·먹이·온도 같은 '해도 된다 vs 안 된다')을 고르고, 사람·가게·특정 판매자를 겨냥한 주제나 의료 판단은 고르지 않는다. 설명엔 양쪽 말을 한 줄씩 적고 "다들 어떻게 생각하세요?" 정도로 끝낸다.
- **말투**: `personas.json` 의 `voice`(아저씨·아줌마·20대·귀여움)와 `tone` 을 따른다. 크루끼리 문체·길이·이모지 습관이 달라야 한다. 매 글 끝에 해시태그·홍보 문구를 붙이지 않는다. 자세한 기준과 고친 예는 `references/natural-voice.md`.
- **제목**: "~하는 법", "~ 이유", "~ 정리"처럼 정보글 제목으로 쓰지 않는다. 상황이나 감정이 보이게("날파리 때문에 미치겠네요ㅠ").
- **정확성**: 사육 정보(온도·습도·먹이 주기)는 일반적으로 받아들여지는 범위로 쓴다. 확실하지 않으면 "저는 이렇게 했어요" 경험형으로 쓴다.

## 댓글 쓰는 법

- 글 본문을 읽고 그 내용에 직접 답한다. "좋은 정보네요" 같은 빈 댓글은 쓰지 않는다.
- 우선순위: ① 크루 아닌 사람의 **답 없는 질문** ② 댓글 0개인 크루 아닌 글 ③ 크루 글(크루끼리 대화로 질문에 답하는 흐름을 만든다).
- 한 글에 크루 댓글은 최대 2개. 같은 크루가 같은 글에 두 번 쓰지 않는다(스크립트도 막는다).
- 그 분류 댓글 크루 3명이 단다. 그중 종이 맞는 크루(`species`)가 먼저 답하고, 모르는 종이면 경험담 대신 공감·추가 질문만 한다.
- 크루가 연 토론엔 그 분류 댓글 크루가 각자 한쪽 편을 골라 이유를 한 줄로 단다(셋이 같은 편이 되지 않게).
- 대댓글(`parentId`)은 기존 댓글에 이어 말할 때만 쓴다.
- **한 댓글에 한 가지만**(팁 하나·경험 한 장면·되묻기 하나). 절반은 한 줄(40자 이하)로 쓰고, 150자 넘는 댓글은 열에 하나만. 매번 되묻거나 "축하드려요!"·"저도~"로 시작하지 않는다(`lint` 가 분포를 본다).

## 좋아요·팔로우

- 좋아요: 내용이 괜찮은 글에만. 크루 아닌 사람의 글을 우선하고, 한 글에 크루 좋아요는 최대 5개.
- 팔로우: 크루의 종과 맞는 사람을 팔로우한다(같은 종 글을 쓴 사람). 크루끼리도 같은 종이면 팔로우한다. 이미 팔로우했으면 스크립트가 건너뛴다(토글이라 다시 누르면 풀린다).

## 보고

실행 뒤 사용자에게: 실행 수(성공·건너뜀·실패), 만든 글 제목 목록, 실패 원인, 기록 파일 경로. 화면 변화가 없는 운영 작업이라 스크린샷은 찍지 않는다.
